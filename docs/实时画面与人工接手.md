# 实时画面与人工接手

## 结论

技术上可以增加 GUI 模式，让 AI 操作剪映窗口，你看到鼠标点击、素材拖动、时间线变化和预览。但**当前发布版尚未实现实时 GUI 控制、暂停接管按钮或窗口热加载**。

你现在就能使用的是“AI 写一轮 → 打开预览 → 你修改并保存 → AI 重新读草稿继续”的分阶段协作。

## 为什么现在不推荐一直打开同一个草稿

目前 AI 修改磁盘上的草稿，剪映编辑器操作自己的内存状态。剪映可能不加载外部更改，也可能在下一次自动保存时把磁盘内容写回旧版本。实时看到窗口，并不等于磁盘改动自动同步。

因此，当前文件模式下 AI 写目标草稿前先返回首页。不能以“窗口已打开”为条件就同时让两个编辑者写同一份工程。

## 当前可执行的接手流程

1. 告诉 AI：“完成初剪后停在已保存结果，等我预览。”
2. AI 保存并报告结果后，打开目标草稿观看。
3. 你调整文字、片段或音频，等待剪映保存，返回首页。
4. 告诉 AI：“已保存并返回首页，重新读取最新草稿，只修改……”。
5. AI 接续处理最新内容，保留你手动做的其他调整。

若你手动加入了复杂转场/特效，预览和最终导出优先在剪映里进行。基础 MP4 渲染不是这些效果的验收工具。

## 后续 GUI 模式的设计范围（未实现）

- 用可读取当前窗口状态、截图并控制鼠标键盘的本机工具操作剪映。
- AI 操作时你观看，不同时抢鼠标；你请求暂停后，停止排队中的动作，才交给你。
- 人工接手期间停止 AI 的 GUI 操作与文件写入。
- 你说继续后，重新读取窗口、时间线和已保存草稿，不能沿用接手前的坐标或旧状态。
- GUI 模式中剪映是主要写入者；如需文件批处理，先正常保存并返回首页，再切换模式。
- 将实时操作、人工接手、恢复续剪与原生导出分别验收，不能用“能打开草稿”代替这些测试。

skill 本身只是一套说明与代码。能否实时控制桌面，还取决于运行它的 harness 是否提供本机 GUI 工具；只具备文件和 Python 工具的 harness 不会因为安装 skill 就自动获得窗口控制能力。
