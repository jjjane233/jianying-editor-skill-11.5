# 中文使用文档

## 1. 这套工具怎么帮你剪视频

你提供素材目录和剪辑要求，AI 读取 skill、制定片段清单，再调用本机 Python 生成或修改剪映草稿。你在剪映里预览、继续调整，最后导出视频。

目前主要是**写草稿文件**，不是在窗口里自动拖动鼠标。能看到完成后的时间线，并不代表已经支持实时 GUI 操作。

## 2. 环境准备

- Windows，剪映专业版 `11.5.0.14471`。
- 64 位 Python 3.10 或以上；本机既有测试使用 Python 3.10。
- 素材在这台电脑上，文件保持原位。草稿记录素材路径，不自动把视频全部打包进仓库。
- 使用完整下载的仓库或完整 skill 文件夹，不能只复制 `SKILL.md`。
- AI harness 能读写本地文件并执行 Python。纯云端聊天不能直接访问你的本机 DLL 和素材。

在仓库根目录打开 PowerShell：

```powershell
python -m pip install -r requirements.txt
python -X utf8 tools/preflight.py
```

可以用 `py -3` 替代 `python`。如果你用虚拟环境，后面的命令全部使用同一个环境的 Python。

预检会显示 Python 位数、剪映 DLL、依赖、首页索引位置以及可探测的草稿目录。必须先在剪映正常创建并保存过一个普通草稿；无法确定实际草稿根目录时，在 `cut` / `build` 中使用 `-o` 明确指定。

本工具不下载剪映，不改变剪映授权，也不需要关闭草稿加密。

## 3. 让 Codex 调用 skill

### 方法 A：不安装，直接指定文件

在 Codex 中打开本仓库作为项目，然后发送：

```text
读取当前仓库的 skills/jianying-editor-11-5/SKILL.md，按其中的流程执行。
素材目录：D:\视频素材
要求：竖屏，每段3秒，总共12秒，加标题“产品展示”。
新建草稿：AI_产品展示
保存后检查时间线、素材路径和首页登记，报告实际时长及草稿位置。
```

如果聊天不在这个仓库里，必须使用实际绝对路径，例如：

```text
读取并使用 C:\work\jian-ying-skill\skills\jianying-editor-11-5\SKILL.md。
```

以上 `C:\work`、`D:\视频素材` 是可替换的示例路径，不是固定安装要求。

### 方法 B：放入本机 Codex 技能目录

仓库附带一个复制工具，不会自动安装或覆盖已有同名技能：

```powershell
python -X utf8 tools/install_skill.py
```

默认目标是 `$CODEX_HOME/skills/jianying-editor-11-5`；未设置 `CODEX_HOME` 时使用用户目录下 `.codex/skills/jianying-editor-11-5`。工具会输出实际位置。它只复制文件，不改变 Codex 设置。

重新打开 Codex 或新建聊天后，检查技能是否出现在当前客户端的技能列表。**复制成功与客户端已经发现技能是两件事。** 支持该调用语法且已发现技能的客户端可以发送：

```text
$jianying-editor-11-5
把 D:\视频素材 剪成横屏，每段4秒，总共20秒，加标题“旅途记录”，新建草稿“AI_旅行”。
```

如果技能没出现，直接使用方法 A，或通过安装工具的 `--destination` 指定你所用客户端实际扫描的技能根目录。不同 harness 的发现机制可能不同。

本仓库自带的安装工具是文件复制工具，不等同于 OpenAI 官方安装器；以你当前 Codex 客户端支持的技能目录为准。

## 4. 其他 harness 如何调用

让代理读取同一个 `SKILL.md`，并从 skill 的 `scripts` 目录执行命令即可，无需依赖 Codex 专属 API：

```powershell
cd "C:\work\jian-ying-skill\skills\jianying-editor-11-5\scripts"
python -X utf8 -m jyai.cli cut "D:\视频素材" --prompt '竖屏 每段3秒 总共12秒 加标题 "产品展示"' --name "AI_产品展示"
```

素材分析、计划和实际执行由 harness 负责。不能执行本地代码的 harness 只能提供方案，不能直接生成这台机器的原生草稿。

## 5. 不通过 AI，直接生成草稿

### 双击入口

双击仓库根目录 `一句话剪视频.bat`，依次输入素材目录、剪辑要求、草稿名称；草稿输出目录可以留空自动探测，或填实际目录。

启动器优先使用环境变量 `JY_PYTHON` 指定的 Python，其次使用 `py -3`，最后使用 `python`，不绑定开发者机器上的 Python 路径。

### 命令行入口

```powershell
python -X utf8 jianying.py media "D:\视频素材"
python -X utf8 jianying.py cut "D:\视频素材" --prompt '竖屏 每段3秒 总共12秒 加标题 "产品展示"' --name "AI_产品展示" -o "D:\剪映草稿"
```

省略 `-o` 时自动探测已有首页索引中的草稿根目录；可通过 `JY_DRAFTS_ROOT` 设置默认目录。素材按文件名排序，默认最多使用 20 个素材；`--recursive` 递归查找，`--limit 50` 修改数量上限。素材太少或太短时，实际视频可能短于目标总时长。

每次新建使用不同名称。名字已存在时主要引擎会报错，而不是默认覆盖。

### 规则解析器的边界

可以识别竖屏/横屏/方形、每段秒数、总时长、引号内文字、帧率、静音等规则。它不独立识别人脸、理解剧情、转录口播，也没有真正的音乐节拍检测。文件夹中有音频时，简单流程可能自动使用第一条音频；需要明确音频安排时使用精确清单。

“自动找精彩片段”“把口播剪紧凑”需要 AI 实际分析素材后安排时间点，不能只把这些字传给规则解析器并宣称已经理解。

## 6. 精确指定剪辑清单

参考 `examples/spec.example.json`。把 `material_dir` 改成自己的素材目录，将示例文件名换成真实素材：

```json
{
  "name": "AI_精确剪辑",
  "material_dir": "D:/视频素材",
  "width": 1080,
  "height": 1920,
  "fps": 30,
  "video": [
    {"path": "01.mp4", "source_start": 1, "start": 0, "duration": 3},
    {"path": "02.mp4", "source_start": 2, "start": 3, "duration": 3}
  ],
  "audio": [],
  "text": [
    {"text": "产品展示", "start": 0, "duration": 3, "size": 9, "x": 0, "y": -0.55}
  ]
}
```

字段含义：`source_start` 是原素材中从哪里截取，`start` 是放在成片的第几秒，`duration` 是片段长度；时间都以秒为单位。相对素材路径按 `material_dir` 解析；未填它时按命令运行目录解析，而不是自动按 JSON 所在目录。

```powershell
python -X utf8 jianying.py build "examples/spec.example.json" -o "D:\剪映草稿"
```

指定只生成、不登记首页的隔离工程：

```powershell
python -X utf8 jianying.py build "examples/spec.example.json" -o "D:\隔离测试草稿" --no-register
```

这种工程不会自动出现在剪映首页。

## 7. 在剪映里查看、修改，再让 AI 接着剪

当前推荐流程：

1. 目标草稿尚未打开，或已经从编辑器返回剪映首页。
2. AI 生成/修改一轮，写入并回读检查完成。
3. 在首页打开该草稿，预览时间线。
4. 你调整片段、文字、配乐，让剪映保存完成，再返回首页。
5. 告诉 AI：继续处理哪个草稿、你改了什么、下一轮想改什么。
6. AI **重新读取最新草稿**，只做指定增量修改，不能重新用旧清单覆盖整条工程。

可以直接这样说：

```text
我已手动调整并保存“AI_产品展示”，现在已返回首页。
重新读取这个草稿的最新内容，不要从旧方案重新生成。
保留我的片段顺序和配乐，只增加一句“新品上市”，显示在第3到第6秒。
完成后告诉我修改结果，等我预览后再进行下一轮。
```

`patch` 支持添加视频/音频/文字、按片段 ID 删除、调音量与修改时间点。它不是任意复杂特效的全功能编辑器。人工新增复杂效果后，优先在剪映内调整并导出；外部增量修改要保留未触及字段并复核效果。

调用实例（需要具体草稿目录，`patch` 不接受单独的草稿名称）：

```powershell
python -X utf8 jianying.py patch "D:\剪映草稿\AI_产品展示" "examples/edits.example.json"
```

现有代码没有可靠的“当前草稿正在被剪映编辑”锁定检测，必须按以上流程人工切回首页。仅打开其他草稿观看，不等于正在编辑目标草稿。

## 8. 导出视频

**优先使用剪映原生导出**：打开草稿、预览检查、点击右上角“导出”。能正确显示草稿并不等于已验证原生自动导出接口。

基础顺序单视频轨也可以直接渲染 MP4：

```powershell
python -X utf8 jianying.py render "AI_产品展示" -o "D:\导出\产品展示.mp4"
```

这是 FFmpeg 基础渲染，支持连续裁剪、画幅适配、基础文字与音频，不保证与剪映的字体、布局、画面裁切完全一致。多视频轨、复杂特效、转场、贴纸等工程需要在剪映原生导出；基础渲染器会拒绝它检测到的不支持结构。

## 9. 常见问题

### 首页不出现草稿 / 显示 0.0B

- 查看命令是否完成、是否使用了 `--no-register`。
- 查看输出中的实际目录和素材是否存在。
- 草稿大小是本地引用素材大小，不是最终 MP4 文件大小。
- 新草稿卡片未刷新时，先正常退出剪映再启动，避免直接覆盖正在编辑的工程。
- 对指定生成草稿检查/修复：

```powershell
python -X utf8 jianying.py inspect "D:\剪映草稿\AI_产品展示"
python -X utf8 jianying.py repair "AI_产品展示"
```

修复会备份草稿。修复流程针对普通视频草稿，不用于无限画布工程。

### 有大小和时长，但是打不开

检查是否是已验证的剪映版本、是否有原生 `videoeditor.dll`、素材路径是否失效。11.5 草稿不仅是首页登记：内容 ID 必须对应活动时间线、schema 和原生编解码也必须一致。不要把 5.9 明文 JSON 直接当成 11.5 可用草稿。

### AI 改了但窗口里没变化 / 一会儿又变回旧内容

剪映不可靠地热加载外部修改，自动保存也可能覆盖它。返回首页，让 AI 完成修改，再重新打开。

### 缺少 Python 模块

在执行工具所用的同一个 Python 环境运行：

```powershell
python -m pip install -r requirements.txt
python -X utf8 tools/preflight.py
```

### 草稿目录识别不正确

使用 `-o` 指定真实目录；上游 API `JyProject` 请显式传 `drafts_root`。运行 `status` 可查看首页索引位置，`list --root` 可查看指定目录内草稿：

```powershell
python -X utf8 jianying.py status
python -X utf8 jianying.py list --root "D:\剪映草稿"
```

### 能否换成其他版本？

需要重新验证那个版本的 DraftIO ABI 与草稿 schema。当前只确认 `11.5.0.14471`，安装更新后不能直接假定仍然兼容。

## 10. 验证与实验功能

```powershell
python -X utf8 -m unittest discover -s tests -v
python -X utf8 tests/smoke_native.py
```

第一条测试发布入口与基础规则；第二条在临时目录生成并解码原生草稿，不登记剪映首页，也不改变正在编辑的草稿。它不是 GUI 打开测试。

上游导出 Agent、画布桥接、Frida 与加密开关相关代码是保留的历史/实验功能，不是本版本基础剪辑的依赖，不在本次稳定使用文档的验收范围内。不要把存在某个接口当成它已经适配并通过验证。
